# 第七章 项目总结与展望

## 7.1 项目总结

### 7.1.1 完成情况

本项目按照预定目标，成功开发了一款完整可运行的移动端塔防 Roguelike 游戏——**Space Frontline（星际前线）**。项目涵盖了从需求分析、架构设计、编码实现到测试验证的完整软件开发流程。

|---|---|

### 7.1.3 使用的关键技术

- **Flutter**：跨平台 UI 框架，Widget 体系，路由导航，`ValueNotifier` 状态管理
- **Flame 1.26.1**：2D 游戏引擎，组件树，游戏循环，精灵动画，碰撞检测
- **Dart mixin**：`EliteTrait` 统一精英类型判断
- **面向对象设计**：继承（Enemy → NurseEnemy/JingLeiEnemy）、组合（BuffManager 作为 Component）、多态（expValue getter）
- **SharedPreferences**：轻量级本地持久化
- **audioplayers**：BGM 播放与场景切换
- **Canvas 绘制**：炮管旋转、雷达图、发光效果、锯齿闪电等程序化绘制

### 7.1.4 遇到的主要问题及解决方案

| 问题 | 解决方案 |
|---|---|
| Flame 组件与 Flutter Widget 混合渲染冲突 | 采用单向 `ValueNotifier` 通信，Flutter 层轮询而非直接在 Flame 渲染期间操作 Widget |
| 道具飞入动画崩溃（MediaQuery 在 Timer 中不稳定） | 重构为纯 Flame `PositionComponent`，在引擎内部渲染动画 |
| 3 种精英敌人的统一判断（不同父类无法共用基类） | 使用 Dart `mixin` 创建 `EliteTrait` 标记接口 |
| 多源燃烧效果如何避免数值失控 | 设计"同源覆盖、异源叠加"规则，用 `Map<BurnSource, double>` 独立追踪 |
| 惊雷汲取完成后属性一次性锁定 | 使用 `_drainPhaseComplete` 标志位 + 查表赋值，确保属性不可变 |
| 大型精灵表加载导致首帧卡顿 | 实现 `static preload()` 模式，在 `onLoad()` 阶段异步预加载 |

### 7.1.5 知识收获

通过本项目的开发，掌握了以下知识和技能：

1. **Flutter 应用开发**：熟练使用 Widget 树、路由管理、状态管理和生命周期
2. **Flame 游戏引擎**：深入理解组件树架构、游戏循环、精灵动画和碰撞检测
3. **游戏架构设计**：分层架构、数据驱动设计、回调松耦合、Mixin 类型标记
4. **移动端性能优化**：资源预加载、对象生命周期管理、避免每帧创建对象
5. **软件工程实践**：版本控制（Git）、代码规范（Dart lint）、文档撰写、测试验证

## 7.2 项目不足

### 7.2.1 内容层面

1. **关卡数量不足**：仅实现了 1 个可用关卡（其余 4 个为占位），游戏内容的丰富度不够
2. **音效缺失**：目前仅实现了背景音乐，缺少射击音效、命中音效、击杀音效和 UI 交互音效
3. **敌人种类可扩展**：4 种敌人虽然行为各异，但更多类型可以进一步丰富策略深度
4. **Buff 平衡性未充分调优**：部分 Buff（如无人机扩充）在单局中过于强势，部分 Buff 使用率偏低

### 7.2.2 技术层面

5. **游戏主类过于臃肿**：`DefendTheTowerGame` 约 1712 行，波次管理、碰撞检测、Buff 应用等逻辑集中在一个文件中，可拆分为多个子系统
6. **缺少单元测试**：项目没有自动化测试，所有验证依赖手动功能测试
7. **屏幕适配不够完善**：在极端长宽比设备（如折叠屏）上可能存在 UI 布局问题
8. **对象池缺失**：子弹和特效采用"创建-销毁"模式，高负载时 GC 压力较大
9. **缺少云端存档**：仅使用本地存储，换设备后天赋数据丢失

### 7.2.3 体验层面

10. **缺乏新手引导**：新玩家可能不理解 Buff 选择、道具使用和敌人机制
11. **暂停菜单过于简陋**：游戏内仅提供返回按钮，缺少真正的暂停菜单（设置、重新开始等）
12. **无设置页面**：缺少音量控制、画质选项等常规设置功能

## 7.3 后续展望

### 7.3.1 内容扩展

- **增加更多关卡**：设计不同的背景、波次配置和敌人组合，每关提供独特的挑战
- **增加更多敌人类型**：如护盾型（需要特定伤害类型击破）、分裂型（死亡后分裂为小敌人）、隐身型（间歇性不可被瞄准）
- **增加更多 Buff**：设计新的元素体系或现有元素的更多选择，增加流派多样性
- **增加更多道具**：如护盾发生器（临时护盾）、引力炸弹（将敌人拉向爆炸点）
- **增加角色系统**：多个可选防御塔（不同初始属性或技能）

### 7.3.2 技术优化

- **代码重构**：将 `DefendTheTowerGame` 拆分为 `WaveManager`、`CollisionSystem`、`BuffApplicator` 等独立模块
- **对象池**：为子弹和特效实现对象池，减少频繁创建销毁的 GC 开销
- **单元测试**：为 Buff 数值计算、波次递增逻辑等核心系统编写测试用例
- **CI/CD**：配置 GitHub Actions 自动运行 `flutter analyze` 和 `flutter test`

### 7.3.3 游戏体验提升

- **新手引导系统**：首次游戏时提供分步教程
- **设置页面**：提供音量调整、画质选择、语言切换
- **暂停菜单优化**：提供"继续""重新开始""设置""返回主菜单"等完整选项
- **成就系统**：设计击杀数、通关、特定 Build 等成就，增加长期追求
- **网络排行榜**：提交分数到云端，提供好友竞争

### 7.3.4 跨平台发布
